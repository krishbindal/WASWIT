# MTE Claims and Limitations

## Valid Claims

- WASWIT implements deterministic runtime selection.
- The policy is empirically derived from targeted micro-benchmarks.
- The policy is frozen (`1.0.0-final`) and immutable for the SDK.
- WASWIT supports identically-functional JavaScript and WebAssembly implementations for its workloads.
- The SDK exposes simple developer-facing execution via `waswitRun()`.
- The package was tested through an isolated Vite consumer application.
- Research artifacts are hash-verified and statically proven.
- The evaluation analysis did not establish statistically significant differences under the multiplicity-adjusted testing procedure.

## Invalid / Overstated Claims (DO NOT MAKE)

- **DO NOT CLAIM** WASWIT always selects the fastest runtime.
- **DO NOT CLAIM** WASWIT is AI-powered.
- **DO NOT CLAIM** WASWIT uses machine learning.
- **DO NOT CLAIM** WASWIT automatically optimizes arbitrary JavaScript code.
- **DO NOT CLAIM** WASM is always faster than JavaScript.
- **DO NOT CLAIM** WASWIT has zero overhead (overhead exists, though typically < 0.1ms).
- **DO NOT CLAIM** WASWIT is universally optimal.
- **DO NOT CLAIM** Results generalize to all browsers/devices.
